Target product

The reaction-time task

Build one index.html page with a welcome screen, ten reaction-time trials, a results screen, and a histogram that compares the current session with an anonymous aggregate.

Your role is lead investigator. Gemini—or another instructor-approved AI coding assistant—may generate and revise code, but you must give precise requirements, test every behavior, protect the data, and be able to explain the finished system.
Build sequence

Five phases

1

Prepare private data storage

Create a Google Sheet named RT_Experiment_Data with the headers Timestamp, Random_Participant_Code, Trial_Number, and Reaction_Time. Keep the sheet private and share its view-only link only through the course portal.

2

Build the Apps Script endpoint

Ask the coding assistant for a validated doPost(e) that accepts only the random code, trial number, and reaction time, adds a server timestamp, and appends one row per trial. The public doGet(e) response should contain aggregate histogram bins and counts—not rows, identifiers, or raw trial records.

3

Build the browser task

Generate a random session code automatically. Present a circle at a random valid screen location; record the click latency; hide it; wait about 500 ms; and repeat until exactly ten trials are complete. Submit the ten records only after successful completion.

4

Visualize feedback

Calculate the current user's average reaction time. Use Chart.js or an equivalent library to plot the aggregate histogram returned by the endpoint and add a clear marker for the current average.

5

Test and publish

Test blank and repeated starts, all ten trials, small screens, failed requests, and chart loading. Publish the task with GitHub Pages and retest the live URL before submitting it in Canvas.

Prompting pattern

Tell the assistant what success means

Build one phase at a time. Paste error messages back exactly and ask for the smallest targeted correction.

Include in every build prompt

  • The current phase and desired output
  • Exact field names and trial count
  • Screen-by-screen behavior
  • Privacy and access constraints
  • Failure and retry behavior
  • A checklist of acceptance tests

Ask during review

  • Can the task submit twice?
  • Can the circle appear partly off-screen?
  • Does timing begin only when the circle appears?
  • What happens when the network fails?
  • Can any public request reveal raw records?
  • Does the live deployment pass all ten trials?
Required safeguard

Practice privacy from the first prototype

Do not collect names, emails, student IDs, free text, or browser fingerprints. Generate a new random code in the task, keep the Google Sheet private, submit its link only through Canvas, and expose only aggregated comparison data from the public endpoint. Never place the sheet or Apps Script management link on this website or in a public README.
What to submit

Four deliverables

1

Live experiment

A public GitHub Pages URL where the ten-trial task and histogram work.

2

Codebase

The GitHub repository containing the frontend and documentation, without secrets or private data links.

3

Private database link

A view-only Google Sheet link submitted privately in Canvas so the instructor can verify the ten trial rows.

4

AI reflection

At most two paragraphs describing the hardest instruction, a specific bug, and how your prompts changed during debugging.
